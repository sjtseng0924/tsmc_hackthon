tNote 系統事故結案報告 (Post-Mortem Report)

文件編號: INC-20231012-03
報告日期: 2023-10-13
事件標題: 因對 Gemini API 的請求負載過大導致的 AI 助理無回應事件


1. 基本資訊

Issue 發生時間: 2023-10-12 11:00 UTC

Issue 解決時間: 2023-10-12 14:00 UTC (服務功能回滾並恢復)

事件等級: P2 (核心功能障礙)


2. 報案問題

多位使用者回報，在使用 tNote 內建的 AI QA Assistant 功能時，AI 沒有任何回覆，使用者介面上的讀取圖示會一直旋轉，直到瀏覽器超時。

問題似乎只發生在某些特定的筆記本上。


3. 影響範圍

服務影響:

AI QA Assistant 功能在處理特定類型的文件（特別是包含複雜圖表的 PDF）時完全不可用。

使用者影響:

依賴 AI 功能從大型文件中提取資訊的使用者工作流程受阻。

資料影響:

無資料遺失。 此為 AI 功能的可用性問題。


4. Issue 發生細節描述

根本原因 (Root Cause):
一個新部署的 PDF 文字解析庫 (pdf-parser v4.2.0) 存在 bug，在處理包含大量向量圖形或嵌入式物件的 PDF 文件時，會產生一個體積異常巨大的文字檔（Payload）。後端服務在未經校驗的情況下，將這個超大文字檔作為上下文（Context）發送給 Gemini 2.5 Flash API，導致 API 請求處理時間過長，最終引發後端服務的 HTTP 客戶端超時。

事件細節:

錯誤的文字提取: 新版的 pdf-parser 庫試圖將 PDF 中的向量圖形（如流程圖、圖表）轉換為冗長的 XML 或 SVG 文字描述，而不是像舊版一樣直接忽略它們。這導致一個 5MB 的 PDF 可能會被解析成一個超過 15MB 的純文字字串。

缺乏請求前驗證: 我們的 AI 服務在呼叫 Gemini API 之前，沒有對準備發送的上下文內容大小進行驗證。它直接將這個 15MB 的巨大字串作為請求的一部分發送出去。

客戶端超時: 雖然 Gemini API 可能正在努力處理這個巨大的請求，但我們的後端服務的 HTTP 客戶端設定了 60 秒的超時限制。在等待 60 秒後，客戶端放棄等待並拋出一個超時異常。然而，這個異常沒有被妥善處理並向前端返回一個明確的錯誤訊息，導致前端介面繼續無限期地等待。

事件時間軸:

10:45 UTC: 包含新版 pdf-parser v4.2.0 的 AI 服務部署上線。

11:00 UTC: 市場部門的一位使用者在一個包含多張複雜分析圖表的市場報告 PDF 上使用 AI 助理，首次觸發此問題並回報。

11:30 UTC: War room 成立。工程師初步檢查發現：

Google Cloud Status 顯示 Gemini API 服務正常。

我們的 API 金鑰有效。

AI 服務的基礎設施（CPU、記憶體）指標正常。

12:15 UTC: 工程師發現所有回報問題的使用者，其筆記本中都包含了大型、圖文並茂的 PDF 文件。

12:45 UTC: 在 Staging 環境中，工程師成功重現了問題。通過增加詳細日誌，他們發現了在呼叫 Gemini API 之前，生成的上下文文字大小達到了驚人的 15.2 MB。

13:30 UTC: 確認問題源於 pdf-parser v4.2.0 的行為變更，鎖定為根本原因。


5. 解決方案 (Immediate Fix)

緊急回滾 (Rollback): 立即將 AI 服務的部署版本回滾到使用 pdf-parser v4.1.8（舊的穩定版本）的狀態。

部署與驗證: 重新部署服務，並請回報問題的使用者驗證 AI 功能在其文件上已恢復正常（即使可能無法理解圖表內容）。


6. 之後如何避免 (Prevention Measures)

行動項目 1: 實施請求負載保護 (Request Payload Guardrail)

內容: 在呼叫任何外部 LLM API 之前，強制執行一個驗證步驟。如果生成的上下文大小超過一個預設的、合理的閾值（例如 1MB 或 1.5M tokens），則立即中斷操作，並向使用者返回一個明確的錯誤訊息：「文件內容過於複雜，AI 無法處理，請嘗試簡化文件或選取部分文字。」

負責人: AI Team

截止日期: 2023-10-20

行動項目 2: 設定並處理合理的 API 超時

內容: 為所有外部 API 呼叫設定更積極的超時時間（例如 30 秒）。更重要的是，必須在程式碼中捕獲超時異常，並向前端返回一個標準化的錯誤狀態，而不是讓前端無限期等待。

負責人: Backend Team

截止日期: 2023-11-01

行動項目 3: 引入非同步處理架構

內容: 對於像 AI 問答這種可能耗時較長的任務，應改為非同步處理。使用者提交問題後，後端立即返回一個「任務已接收」的狀態，並在背景中處理。前端透過輪詢或 WebSocket 來獲取最終結果或錯誤訊息。這能極大改善使用者體驗。

負責人: Architecture Team

截止日期: 2024-Q1

行動項目 4: 建立第三方庫的迴歸測試集

內容: 建立一個包含各種「邊緣案例」文件的測試集（例如：超大文件、純圖片 PDF、複雜向量圖 PDF、加密文件等）。在升級任何核心的第三方函式庫（如 pdf-parser）之前，必須先用這個測試集進行迴歸測試，確保其行為符合預期。

負責人: QA Team

截止日期: 2023-11-15
