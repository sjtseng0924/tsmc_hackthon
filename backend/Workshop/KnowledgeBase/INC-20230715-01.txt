tNote 系統事故結案報告 (Post-Mortem Report)

文件編號: INC-20230715-01
報告日期: 2023-07-18
事件標題: 因自動化腳本錯誤導致的服務中斷與資料不可見事件


1. 基本資訊

Issue 發生時間: 2023-07-15 00:00 UTC

Issue 解決時間: 2023-07-15 04:30 UTC (服務功能恢復), 06:00 UTC (資料完全同步)

事件等級: P0 (嚴重服務中斷)


2. 報案問題

使用者回報無法建立新的筆記，或上傳檔案時出現「Internal Server Error」。

部分使用者回報，在 00:00 UTC 之後新增的筆記內容「消失不見」。


3. 影響範圍

服務影響:

檔案上傳功能完全中斷。

筆記的新增與編輯資料無法即時顯

使用者影響:

全球所有使用者。

資料影響:

無資料永久遺失。 資料成功寫入主資料庫，僅因複製中斷而暫時不可見。


4. Issue 發生細節描述

根本原因 (Root Cause):
一個新版本的日誌歸檔腳本 log_archive_utility_v3.py 在 2023-07-14 部署上線，並於 2023-07-15 00:00 UTC 首次在生產環境執行。該腳本存在兩個致命缺陷：

權限過高與錯誤操作: 為了清理磁碟空間，腳本中包含了一段意圖重啟日誌服務的程式碼。但由於錯誤的配置，它執行了 systemctl restart systemd-networkd，重啟了伺服器的核心網路服務。這導致伺服器防火牆規則被重置為預設狀態，阻斷了主從資料庫之間用於資料複製 (Replication) 的特定端口連線。

環境變數汙染: 該腳本中遺留了一行用於測試的程式碼 export AWS_ACCESS_KEY_ID=""，此行程式碼在執行時，清空了後端服務運行的環境變數中的 AWS 存取金鑰。導致後端服務在嘗試向 S3 儲存桶寫入檔案時，因缺乏有效憑證而被拒絕，返回「Internal Server Error」。

事件時間軸:

00:00 UTC: log_archive_utility_v3.py 腳本開始執行。

00:01 UTC: 腳本重啟網路服務，資料庫複製中斷。監控系統發出「Replication Lag」警報，但被歸類為次要警報。

00:02 UTC: 腳本清空 AWS 環境變數。後端服務開始向上傳請求返回 500 錯誤。

01:00 UTC (亞洲區上班時間): 客戶支援團隊開始收到大量使用者回報。

01:30 UTC: War room 成立，工程師開始調查。

03:00 UTC: 工程師發現資料庫複製中斷，但找不到網路硬體故障。同時，另一組人確認 S3 權限本身沒有問題，但應用程式日誌顯示「Invalid Credentials」。

03:45 UTC: 團隊將兩個問題的時間點關聯起來，開始懷疑是午夜的排程工作所致。

04:00 UTC: 審查 log_archive_utility_v3.py 腳本後，確認了根本原因。


5. 解決方案 (Immediate Fix)

停用腳本: 立刻從 Cron排程中移除 log_archive_utility_v3.py，防止其再次執行。

恢復網路: 手動將正確的防火牆規則應用到資料庫伺服器，恢復主從資料庫之間的連線。

恢復權限: 重新部署 (Redeploy) 後端應用程式服務，使其從配置中心重新載入正確的 AWS credentials。

同步資料: 重啟資料庫複製服務，並手動觸發一次全量同步，確保所有讀取副本的資料與主庫一致。


6. 之後如何避免 (Prevention Measures)

行動項目 1: 實施最小權限原則

內容: 嚴格限制所有自動化腳本的執行權限。任何腳本都不應被授予重啟核心系統服務（如網路、資料庫）的權限。此類操作必須由 SRE 團隊手動執行或透過受嚴格控管的 Ansible Playbook 執行。

負責人: Infra Team

截止日期: 2023-08-01

行動項目 2: 強化程式碼審查 (Code Review) 流程

內容: 建立一個 high-risk 標籤。任何對生產環境有寫入權限、或能影響系統配置的自動化腳本變更，都必須標記為 high-risk，且需要至少兩名資深工程師進行審查批准。

負責人: All Engineering Leads

截止日期: 2023-07-25

行動項目 3: 建立隔離的測試環境

內容: 確保 Staging 環境與 Production 環境在網路策略、權限配置上盡可能一致，以便在部署前能發現此類問題。禁止在腳本中硬編碼或包含針對特定環境的邏輯。

負責人: DevOps Team

截止日期: 2023-09-01

行動項目 4: 提升監控告警等級

內容: 將「資料庫複製延遲超過5分鐘」和「S3 API 錯誤率連續3分鐘超過5%」的警報等級提升至 P1，並直接通知 on-call 工程師。

負責人: SRE Team

截止日期: 2023-08-15
